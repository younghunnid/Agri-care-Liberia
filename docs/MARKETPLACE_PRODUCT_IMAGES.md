# Marketplace product pictures

## Root cause (found 2026-11-21 in the live listings API, read-only, and the code)
Of 33 live listings, **24 are the harvest-demo listings from `server/demoMarket.ts`, whose insert statement hard-codes one image for all of them: `/src/assets/images/liberia_agri_market_….jpg`, the mixed market photograph.** That is every Rice, Cassava, Pepper, Okra, Plantain, supplies and similar harvest listing. The other 9 come from `server/seedPrototype.ts`: they have per-category images, but Pepper and Okra share one combined photo, and compost and cassava cuttings use the general farm hero photograph. Two more contributing causes: the sell form defaulted to the first sample picture (Rice) for every new listing, and `POST /marketplace/listings` falls back to the mixed photograph. The frontend rendered `item.image_url` faithfully (no rendering bug, no load failures: the files exist and are served); the data itself was wrong. No category-to-image mapping existed.

## Fix (display layer; no database change)
`src/data/productImages.ts` is the one mapping. A listing shows (1) the seller's own photo (`data:image/` upload or `/offline-img/`), else (2) a representative illustration chosen by product name (specific words first: eggs, compost, sprayer, cuttings, then rice, cassava, pepper, okra, plantain, maize, chicken, fish, goats), then crop slug, then category, else (3) a neutral illustration. Any `/src/assets/images/...` value is a built-in sample or the old shared default, never a seller upload, so it is no longer trusted to show the product.
- 14 project-made vector illustrations in `public/images/products/*.svg` (about 0.7 to 4.5 KB each, 17 KB total, no external links, in the offline cache). Project-owned: no reuse-rights questions, no hotlinks.
- Cards show a "Representative illustration" badge, the detail page a caption "Representative illustration of … It is not a photograph of this seller's product.", and the alt text says so. A seller's uploaded photo is shown without the label ("Photo supplied by the seller").
- Pictures are lazy-loaded and decoded asynchronously; each card is keyed by listing and picture so filtering or sorting cannot carry a picture to another product.
- The sell form no longer offers mislabelled sample pictures (Rice / Crops, Seeds / Inputs / Tools ...); a seller can upload a photo, otherwise the illustration for their product appears. Editing a listing keeps whatever image value it already has.
- **Not changed:** the 33 live rows, seed scripts (new demo databases still insert the old paths; the display layer corrects them) and the server default. Any change to stored live image values needs a separate review.

## Tests
`npm run test:weather` (includes `tests/product-images.test.ts`: mapping for all live names, seller photos preserved, no external links in the SVGs) and `npm run test:marketplace-images` (browser, synthetic listings: 13 products with 13 different pictures, uploaded photo kept, detail captions, filters and county/category/search without mix-ups, 320/375/1280 px, lazy loading and size, offline cache). The WebKit run covers the first two checks only (its filter step needs separate selector work).
Limitation: illustrations are drawings, not photographs; use real seller photos when sellers upload them. Real-device (iPhone/Android) rendering was not tested.

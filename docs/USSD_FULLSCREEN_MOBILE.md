# Standalone /ussd: fits the phone screen

`/ussd` (the QR destination, unchanged) renders `UssdOnlyPage` + `UssdPhone compact` without the website layout. The page is `h-[100dvh]`; the phone fills it with flex/grid: brand + **Back to Website** in one header row, a display that takes the remaining height (scrolls inside itself only when a long menu does not fit), Call/Send and End, Back/Home/Cancel, the 12-key pad (4 equal rows), and one voice row (Voice on/off, Repeat, Slow/Normal/Fast). Rarely used items (Test voice, Refresh market, identity) are behind **More**. Sizes use `dvh`, `clamp()` and safe-area insets; no transforms. Landscape phones (height <= 520 px) put the display and keys side by side. `/ussd-demo` and the website are unchanged.

Tests: `npm run test:ussd-fit` (12 viewports: 320x568, 375x667, 390x844, 393x852, 430x932, the same phones with 100-110 px less height for Safari's toolbars, and two landscape sizes) checks per viewport: no page scroll, no sideways overflow, no control outside the viewport, text >= 12 px, dialing *440#, registration to the menu with option 9 visible, long-press 0 mute, voice toggle and repeat, an option, Back to Website and back again, reload. Also passes in the WebKit 17.4 runner. These are simulated viewports in desktop browsers, NOT a physical iPhone or Android phone.

Limitations: on phones shorter than about 700 px of visible height the keys are 34-40 px tall (44+ px on 844 px-tall phones); at 460 px height (SE with toolbars) the longest menu scrolls inside the display; if less than 22rem (352 px) is visible the page itself may scroll as a last resort. Safari's dynamic toolbar and the on-screen keyboard (registration forms) were not tested on a real device. The registration form still scrolls the page when it is open.
